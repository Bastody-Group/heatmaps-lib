# heatmaps-lib

Скрипт збирає кліки та глибину скролу користувачів у вашому мокапі та показує їх поверх мокапу як клік-хітмапу і скролмапу.

Потрібно підключити один скрипт, повідомляти йому про зміну екранів і додати один рядок у відправку метрик.

---

## 1. Підключення

Додайте на сторінку мокапу:

```html
<script src="https://cdn.jsdelivr.net/gh/Bastody-Group/heatmaps-lib@v1.0.17/bm.tracking.min.js"></script>
```

Вказуйте конкретну версію (`@v1.0.17`), не `@main` і не `@latest`. Інакше різні користувачі можуть отримати різний код.

Сторінка має відповідати трьом вимогам:

- **Контент мокапу лежить в елементі `#fs-app`.** Без нього скрипт покаже попередження, а позиції кліків будуть неточні.
- **Мокап використовує FullScreen.js.** Запис починається тільки після того, як користувач закрив welcome-екран. Дії на welcome-екрані не записуються.
- **У посиланні на мокап є `UserHash`:**
  ```
  https://example.com/my-mockup/?UserHash=abc123
  ```
  Без `UserHash` дані не відправляться.

---

## 2. Сторінки

Якщо в мокапі кілька екранів, при кожному переході повідомте скрипту назву нового екрана:

```js
document.dispatchEvent(new CustomEvent('bm:page', { detail: 'checkout' }));
```

Кліки й скрол кожного екрана зберігаються окремо, і хітмапа теж показується окремо для кожного.

- Поки ви не відправили жодної назви, все записується під `home`.
- Відправляйте подію **після** того, як новий екран уже показано.
- Назви чутливі до регістру: `checkout` і `Checkout` скрипт вважає різними екранами. Використовуйте завжди одні й ті самі назви.
- Якщо екран у мокапі лише один, цей крок можна пропустити.

---

## 3. Відправка даних

Хітмапи відправляються разом з метриками. Для цього в метод `sendMetrics()`, який є в кожному проєкті, треба додати виклик `window.BM_TRACKER.submit()` паралельно із запитом метрик:

```js
async sendMetrics() {
  try {
    const response = await fetch('<URL метрик>', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(this.mainJson),
      keepalive: true,
    });

    const [data, result] = await Promise.all([
      response.json(),
      window.BM_TRACKER ? window.BM_TRACKER.submit() : Promise.resolve(null), // хітмапи
    ]);

    console.log('bm submit result: ', result);

    return data.JSON_Status === 'Saved';
  } catch (error) {
    console.error('Error in sendMetrics:', error);
    throw error;
  }
}
```

- Перевірка `window.BM_TRACKER ? ... : Promise.resolve(null)` обов'язкова. У режимі перегляду хітмап і на сторінках, де скрипт не підключений, `BM_TRACKER` немає, і без перевірки `sendMetrics()` впаде.
- `submit()` ніколи не кидає помилку, тому не зламає відправку метрик. Він повертає `{ success: true }` або `{ success: false, reason }`, і `reason` пояснює, чому дані не пішли (див. «Якщо щось не працює»).
- Дані відправляються **один раз**. Повторний виклик поверне `reason: 'already-submitted'`.
- Все, що користувач зробить після відправки метрик, у хітмапу не потрапить.
- З локального комп'ютера (`localhost`, `127.0.0.1`, файл, відкритий напряму) дані **не відправляються**, щоб не засмічувати статистику тестами. Якщо все ж треба перевірити відправку локально, додайте **перед** скриптом:
  ```html
  <script>window.BM_ALLOW_LOCAL_SUBMIT = true;</script>
  ```

## Повний приклад

```html
<div id="fs-app">
  <section data-page="home">...</section>
  <section data-page="checkout" hidden>...</section>
</div>

<script src="https://cdn.jsdelivr.net/gh/Bastody-Group/heatmaps-lib@v1.0.17/bm.tracking.min.js"></script>
<script>
  function showPage(name) {
    // ... ваш код, що показує потрібний екран ...
    document.dispatchEvent(new CustomEvent('bm:page', { detail: name }));
  }
</script>
```

Хітмапи відправляються з `sendMetrics()`, як показано в розділі 3.

## Перегляд хітмап

Відкрийте той самий мокап, додавши до посилання параметри:

```
https://example.com/my-mockup/?UserHash=abc123&clickmaps=true&scrollmaps=true
```

| Параметр | Значення | Що показує |
|---|---|---|
| `clickmaps` | `true` / `false` | куди клікали |
| `scrollmaps` | `true` / `false` | до якого місця доскролювали (червоне: майже всі, зелене: мало хто) |
| `scrollpercent` | `true` / `false` | лінія під курсором з відсотком користувачів, які дійшли до цієї глибини |
| `device` | `phone` / `tablet` / `desktop` | сесії з якого типу пристрою показувати |

У цьому режимі нічого не записується, тож ваші перегляди не потраплять у статистику.

Праворуч унизу з'являється панель **Heatmaps**. На ній є:

- перемикачі клік-хітмапи, скролмапи і відсотків;
- вибір пристрою;
- кнопка **Screenshot**, яка зберігає PNG усього мокапу разом з хітмапою;
- кількість завантажених сесій.

Ходіть по мокапу як звичайно: хітмапа перемикається разом з екранами. Налаштування панелі одразу записуються в адресний рядок, тож посилання можна просто скопіювати й надіслати колезі.

## Що можна і що не можна

**Можна**

- Мати будь-яку кількість екранів в одному HTML.
- Скролити як усю сторінку, так і окремі блоки всередині неї.
- Використовувати модалки, дропдауни, каруселі та інший динамічний контент.

**Не можна**

- **Змінювати верстку мокапу після того, як почали збирати дані.** Скрипт запам'ятовує, по якому за рахунком елементу клікнули. Якщо додати, видалити або переставити блоки, старі кліки покажуться не на тих елементах. Якщо верстку треба змінити, робіть нову копію мокапу з новим `UserHash`.
- **Перейменовувати екрани** (назви в `bm:page`) після початку збору. Старі дані лишаться під старою назвою.
- Прибирати `#fs-app` або FullScreen.js.
- Викликати `sendMetrics()` (а отже й відправку хітмап) на початку проходження.
- Викликати `window.BM_TRACKER.submit()` без перевірки, що `BM_TRACKER` існує.
- Підключати скрипт двічі на одній сторінці.

## Якщо щось не працює

Відкрийте консоль браузера (F12 → Console) і подивіться на рядок `bm submit result:`:

| Результат | Причина |
|---|---|
| `{ success: true }` | все добре, дані відправлено |
| `null` | скрипт не підключений, або відкрито режим перегляду (є `clickmaps`/`scrollmaps` в URL) |
| `reason: 'no-user-hash'` | у посиланні немає `?UserHash=...` |
| `reason: 'local-environment'` | мокап відкрито локально (див. розділ 3) |
| `reason: 'already-submitted'` | дані вже були відправлені раніше |
| `reason: 'request-failed'` | проблема з мережею або сервером |

Інші ознаки проблем:

- `alert` з текстом `#fs-app element not found`: на сторінці немає елемента `#fs-app`.
- `Error: failed to load data from endpoint` на панелі: не вдалося завантажити дані для перегляду.

Щоб перевірити, яка версія скрипта завантажилась, введіть у консолі `BM_TRACKING_VERSION`.

Якщо хітмапа порожня, перевірте таке:

- що в посиланні правильний `UserHash`;
- що вибрано потрібний пристрій;
- що ви на тому самому екрані, де клікали користувачі;
- що хоча б один користувач дійшов до відправки метрик.
